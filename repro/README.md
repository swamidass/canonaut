# Reproducing the paper's measurements

Everything reported in *canonaut: A Safe Rust Implementation of the nauty Graph
Canonicalization Algorithm* is produced by the scripts in this directory from
the sources in this repository. Both figures and all three timing tables are
regenerated by the sequence below.

## Prerequisites

* Rust (stable, ≥ 1.85) and a C toolchain
* nauty ≥ 2.8.9 with headers and library under `/usr/local`
  (`./configure --enable-tls && make`, or `brew install nauty`) — needed by the
  `c-nauty-bench` feature and by `benches/c_memcheck.c`
* Python ≥ 3.9 with `matplotlib` for the figures

The published measurements were taken with native codegen on both sides: the C
reference is compiled `-O3 -march=native`, and the Rust side is built with
`RUSTFLAGS="-C target-cpu=native"`, as in the commands below. A plain build
without that flag targets the portable baseline instead.

## 1. Timings (Tables 1–3, Figure 1)

```sh
RUSTFLAGS="-C target-cpu=native" \
  cargo bench --features c-nauty-bench    # writes target/criterion/**
python3 repro/collect_criterion.py        # -> repro/benchmark_data.csv
python3 repro/make_tables.py              # -> repro/tables.tex (LaTeX table bodies)
python3 repro/plot_figures.py             # -> repro/performance_speedup.pdf
```

`benchmark_data.csv` holds the mean and the 95 % confidence interval of the
mean for every (family, implementation, n) point, exactly as reported. It
covers four benchmark groups: `small` (n = 8…128), `scaling` (n = 256…2048),
`hard` (the refinement-blind CFI, Hadamard and Paley instances, all built
in-process by `canonaut::generators`) and `g6_batch`. The same
graph buffer — built once by `canonaut::generators` — is handed to both
implementations, so the two sides canonicalize bit-identical inputs; the C
baseline pre-allocates its output buffers outside the timed region, mirroring
`CanonautManager`'s buffer reuse.

## 2. Memory (Figure 2 and the allocation numbers)

```sh
./repro/measure_memory.sh                 # -> repro/memory_data.csv
                                          #    repro/allocation_data.csv
python3 repro/plot_figures.py             # -> repro/memory_usage.pdf
```

`memory_data.csv` is peak resident-set size from `/usr/bin/time -l`, one
process per data point, for canonaut and C nauty. Peak RSS is dominated by
fixed process overhead below n ≈ 128, so `allocation_data.csv` additionally
records canonaut's own heap traffic, measured with the counting global
allocator in `src/bin/memcheck.rs`: allocations and bytes during set-up versus
during the steady-state canonicalization loop.

## 3. Validation

```sh
cargo test                                # includes the committed
                                          # test_data/smoke corpus (1 965
                                          # graphs) cross-checked against
                                          # pynauty reference forms
./setup.sh                                # regenerates the full corpora and
                                          # runs every test, including the
                                          # #[ignore]d full-corpus comparisons
```

## Machine used for the reported numbers

Apple M1 Max (arm64, 10 cores, 64 GiB), macOS 26.5.1, Rust 1.95.0 (stable),
nauty 2.8.9, Criterion 0.8.
